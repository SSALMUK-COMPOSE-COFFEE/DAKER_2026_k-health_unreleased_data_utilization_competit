# 기술 검증 — Gemini API·코퍼스·선행사례 (2026-07-30)

## 🚨 발견 1 — Gemini API 약관이 임상 사용을 명문으로 금지한다

출처: https://ai.google.dev/gemini-api/terms (Last modified **2026-04-28 UTC**), "Use Restrictions" 원문:

> "You may not use the Services **in clinical practice, to provide medical advice**, or in any manner
> that is **overseen by or requires clearance or approval from a medical device regulatory agency**."

세 가지를 동시에 금지한다. 회피 불가한 약관 사실이므로 **프레이밍 자체를 바꿔야 한다.**

### 대응 — 산출물을 재정의한다

| 하면 안 되는 규정 | 바꿔야 할 규정 |
|---|---|
| "간호사용 임상 의사결정 지원 시스템" | **"연구·교육용 근거 탐색 프로토타입"** |
| 환자 개별 판단·처방 제안 | **약물 단위의 일반적 허가사항 조회에 한정** |
| 간호사에게 직접 제시되는 지시 | **연구자가 검토하는 근거 후보 목록 + 인용** |

그리고 임상 배치 단계에서는 **Vertex AI 경로 + 별도 계약 + 의료기기 해당성 검토**가
선행 조건임을 **한계로 자진 기재한다.** 자진 기재가 실현성 평가에서 오히려 유리하다.

## 🚨 발견 2 — `gemini-2.5-flash-lite`는 대회 기간 중에 퇴역한다

| 항목 | 값 |
|---|---|
| 퇴역 예정일 | **2026-10-16** (출처: ai.google.dev/gemini-api/docs/deprecations) |
| 본선 제출 마감 | **2026-11-06** |
| 대체 권고 모델 | **`gemini-3.1-flash-lite`** |

**본선 분석 기간 중에 EOL이 된다.** 게다가:

**File Search 지원 모델 목록에 2.5 Flash-Lite가 없다.** 지원: Gemini 3.6 Flash, 3.5 Flash-Lite,
3.5 Flash, 3.1 Pro Preview, **3.1 Flash-Lite**, 3 Flash Preview (출처: ai.google.dev/gemini-api/docs/file-search)

File Search는 문서 업로드→청킹→인덱싱을 Google이 대행하고 **응답에 출처 문서명 + PDF 페이지번호
인용을 포함**한다. 2.5를 고집하면 벡터스토어·청킹·인용 추적을 전부 자체 구현해야 한다.

→ **결정: `gemini-3.1-flash-lite`로 전환. EOL과 File Search 두 문제가 동시에 해결된다.**
제안서에는 모델 ID를 하드코딩하지 말고 **"Gemini Flash-Lite 계열"**로 계열 단위 표기 +
모델 교체 가능한 추상화 레이어 + 평가셋 고정(회귀검증)을 명시한다.

## 확인된 사양·가격·정책

| 항목 | 값 | 비고 |
|---|---|---|
| 2.5 Flash-Lite 입력 한도 | 1,048,576 토큰 | 출력 65,536 |
| Structured output / Function calling / Context caching / Batch | 모두 지원 | |
| Knowledge cutoff | 2025-01 | |
| 유료 단가 | 입력 **$0.10** / 출력 **$0.40** per 1M | 무료 티어 존재 |
| `gemini-embedding-001` | 기본 3072차원, 128~3072 가변(MRL), 100+ 언어, 입력 $0.15/1M | MTEB Multilingual 1위(2025-03-10 기준) |
| File Search | 스토리지 무료, 인덱싱 시 임베딩 요금만, **질의 시 임베딩 무료**. 파일당 100MB | 인용 자동 반환 |

### 비용 — 방어하기 가장 쉬운 항목

질의 1건: 청크 5개×600토큰 + 프롬프트 ≈ 3,500 입력 / 500 출력
→ `3500×0.10/1e6 + 500×0.40/1e6 = $0.00055` ≈ **약 0.8원/질의**
1,000건 ≈ **약 800원**. 인덱싱 20MB(≈1,000만 토큰) ≈ **약 2,200원 1회성**.
(단가는 공식 확인, 토큰 추정치는 자체 계산)

→ 비용은 실현성 리스크가 아니다. **강점으로 쓴다.**

### 데이터 학습·보존 정책 → **반드시 유료 티어**

| 티어 | 정책 |
|---|---|
| 무료 | 콘텐츠를 제품 개선에 사용. **인간 검토자가 읽고 주석 가능** |
| **유료** | "Google doesn't use your prompts … or responses to improve our products." 로깅은 정책 위반 탐지 목적만 |

공개 문서만 보내더라도 **유료 티어 사용을 제안서에 명문화한다.** 무료 티어의 인간 검토 조항은
환자 데이터가 없어도 심사위원 앞에서 방어가 어렵다.

## 🚨 발견 3 — 참신성 주장의 경계가 좁아졌다

**"측정값 → 검색질의 → 근거기반 판정" 패턴 자체는 참신하지 않다. 반증됐다.**

| 이미 존재 | 내용 |
|---|---|
| **FHIR-RAG-MEDS** (arXiv 2509.07706) | HL7 FHIR 실시간 환자데이터 + 벡터DB 가이드라인 → 개인화 권고. **패턴 자체를 이미 구현** |
| 웨어러블 센서 → RAG 리포트 | Springer doi:10.1007/978-3-032-24724-7_29 |
| **MEREDITH** (JCO PO, doi:10.1200/PO-24-00478) | **Google Gemini Pro 기반** + RAG + CoT 종양학 치료 권고. **같은 벤더·같은 구조** |
| 가이드라인 RAG 임상의사결정지원 | 포화 상태. NICE(arXiv 2510.02967), ACR(2510.04969), ClinicBot(2605.00846), Guide-RAG(2510.15782) 등 |
| **GC녹십자 RegulAItor** | 의약품 규제업무 전용 RAG 챗봇. 국내 제약업계 최초 실전 배치 |
| AskFDALabel | FDA 라벨 이상반응 추출 LLM+RAG |
| 무선환경·HVAC 센서 RAG | arXiv 2503.07670, 2507.04748 |

### 그러나 다음 세 요소의 교집합은 발견되지 않았다

1. **주입 유량(flow-rate) 실측 데이터** — 스마트펌프 DERS 영역에 LLM/RAG 사례 없음
2. **한국어 의약품 허가사항 코퍼스** — 국내 RAG 사례는 GC녹십자 규제업무용(FDA+사내문서)뿐
3. **"편차 +X%가 허용 범위인가"라는 정량 임계 판정 + 인용 반환**

### 권장 참신성 문구 — 이 수준까지만

> "항암제 정맥주입의 **실측 유량 편차**를 입력으로 하여 **의약품 허가사항(용법·용량) 및
> 간호실무지침 코퍼스**에 대한 검색질의를 자동 생성하고, **인용 가능한 허용범위 판정**을
> 반환하는 파이프라인의 **적용 사례**"

**⛔ 절대 쓰지 말 것**: "최초의 가이드라인 RAG", "센서-RAG 결합 최초", "측정값 구동 검색 최초",
"LLM 임상의사결정지원 최초". 심사위원이 5분 검색으로 반박한다.

## 코퍼스 — 법적으로 인덱싱 가능한 것

### ✅ 안전. 제안서에 명시 가능

| 소스 | 접근 | 라이선스 |
|---|---|---|
| **openFDA drug label** api.fda.gov/drug/label.json | REST API(키 없이 사용 가능) + zipped JSON 벌크 | **CC0 1.0 퍼블릭 도메인** |
| **식약처 의약품 제품 허가정보** data.go.kr/data/15095677 | OpenAPI, 활용신청 필요, 개발계정 월 10,000건 | **"이용허락범위 제한 없음"** |
| **식약처 e약은요** data.go.kr/data/15075057 | OpenAPI, 일 10,000건 | **"이용허락범위 제한 없음"**. 단 OTC 중심이라 항암제 커버리지 불확실 |
| **DailyMed SPL 벌크** | part1.zip(15,165 files, 3GB) + part2.zip(9,923 files, 3GB) | 미국 정부 저작물(퍼블릭 도메인). **페이지에 명시 문구 없음** |

### ★ openFDA 실제 호출로 검증 완료 (2026-07-30)

`dosage_and_administration` 필드에 **주입 시간이 명시적으로 들어 있다.** 실측 결과:

| 성분 | 필드 길이 | 추출된 주입 시간 문구 |
|---|---|---|
| Oxaliplatin | 6,115자 | "as an intravenous infusion **over 120 minutes** concurrently with leucovorin over 120 minutes" |
| Paclitaxel | 10,351자 | "administered intravenously **over 3 hours** at a dose of 175 mg/m²" / "**over 24 hours** at 135 mg/m²" |
| Gemcitabine | 7,782자 | "1000 mg/m² **over 30 minutes** on Days 1 and 8 of each 21-day cycle" |
| Cisplatin | 2,460자 | "infused **over a 6 hour to 8 hour period**" |

→ **코퍼스 기반이 실제로 작동한다.** 우리 데이터의 처방시간 30/60/90/120분을
허가사항 권고 주입시간과 직접 대조할 수 있다. **제안서에 이 표를 사전 검증 증거로 넣는다.**
CC0라 라이선스 리스크도 없다.

### 권장 코퍼스 구성

1. **1차 골격 (라이선스 청정)**: **openFDA drug label (CC0)** — 검증 완료. 법적 근거를 여기에 100% 걸어둔다
2. **국내 대응**: 식약처 의약품 제품 허가정보 OpenAPI — 활용신청 후 용법용량 전문 반환 여부 실측 필요(아래 확인 실패 참조)
3. **간호 수행 근거**: 병원간호사회 말초/중심정맥 주입요법 지침 — **"이용 협의 후 반영"** 조건부 기재
4. **표준 매핑**: RxNorm으로 오염된 약물명 ↔ 성분 ↔ 영문 라벨 연결

| D2 | 국내 의료기기 해당성 | **식약처 「LLM 기반 디지털의료기기 허가·심사 가이드라인」 2026-06-30 발표** (mfds.go.kr/brd/m_1060/view.do?seq=15879). 사용목적+위해도로 구분, 임상적 연관성·분석적 검증·임상적 검증 3단 요구, **"LLM as a judge" 단독 성능검증 불인정**. → 이 최신 가이드라인을 명시 인용하고 "사용목적상 의료기기에 해당하지 않도록 범위를 한정했다"고 선언. **성능평가는 LLM 자동평가에 의존하지 않고 전문가 정답셋 대조로 설계** |
| D3 | 모델 EOL / 벤더 종속 | 계열 단위 표기 + 추상화 레이어 + 평가셋 고정. `gemini-3.1-flash-lite`로 즉시 전환 |
| D4 | 비용 | 질의당 0.8원. 온프레미스 GPU 대비 총소유비용 수 자리수 낮음 |

### 심사위원이 던질 가장 날카로운 한 문장에 대한 준비

> "결국 공개된 의약품 허가사항을 검색하는 건데, 식약처 홈페이지에서 찾는 것과 뭐가 다릅니까?"

**답**: 차별점은 검색이 아니라 **측정값이 질의를 생성하는 자동 연결**과 **정량 임계 판정**이다.
"이 약물의 용법용량은?"이 아니라 **"실측 유량이 처방 대비 +20%일 때 이 약물의 허가사항·간호지침상
허용 가능한가"**를 답한다. 후자는 현재 어떤 조회 서비스도 제공하지 않는다.
**이 문장을 제안서 서두에 둔다.**
