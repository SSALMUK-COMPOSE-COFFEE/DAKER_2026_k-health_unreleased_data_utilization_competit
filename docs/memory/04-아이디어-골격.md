# 아이디어 골격 — 신유량조절기 × RAG (2026-07-30)

> 데이터셋 전환 근거: [제약변경](03-제약변경-데이터셋재선택.md)
> **설명서 원문 판독 결과 반영본**: [원문검증](05-데이터-설명서-원문검증.md)
> 조사 진행 중이므로 통계·인용은 비어 있음. 골격과 분석 설계만 확정.

## 확정된 기술 제약 (사용자 결정)

- 로컬 모델 안 돌림. **Google Gemini 2.5 Flash Lite를 클라우드 API로 사용**
- → 안심존은 폐쇄망이므로 **API 호출이 원천적으로 불가**. 분리 구조가 선택이 아니라 필연
- → 안심존 안: 표 통계만. 안심존 밖: 공개 문서 대상 RAG. **환자 데이터는 API로 절대 나가지 않는다**
- 이 구조가 본선 수행평가 "이용 규정 준수 5점"에서 오히려 유리한 논거가 된다

## 한 문장

항암 수액 주입의 실제 오차가 **그 약물에 허용되는 범위인지**를, 오염된 약물명을
정규화해 근거 문서와 대조하여 판정하는 도구.

## 프레이밍 — "오차가 크다"가 아니라 "±10%는 허용되는가"

설명서 7페이지가 이미 **"오차율 평균값은 설정된 치료 시간 대비 ±10% 이내"**라고 밝혔다.
따라서 "오차가 크다"를 전제로 하면 설명서와 정면충돌하고 즉시 깨진다.

살아 있는 질문은 이것이다. **설명서는 오차가 작다고 했을 뿐, 그 오차가 약물별로
임상적으로 허용되는지는 말하지 않았다.** 120분 주입의 ±10%는 ±12분이다.
어떤 항암제에는 무해하고 어떤 항암제에는 허가사항 용법용량을 벗어난다.
그 판정에는 약물별 권고 주입 조건이 필요하고, 그건 데이터가 아니라 문서에 있다.

→ 오차의 **크기**를 다투지 않고 오차의 **허용 여부**를 다툰다. 이게 RAG 층의 존재 이유다.

## 왜 이 데이터로만 가능한가

설명서에 명시된 구조가 정확히 이 질문에 맞춰져 있다.

- **8개 실험군**: 수액높이(150·200cm) × 처방시간(30·60·90·120분) × 수액종류(NS·5% D/W), 총 120회
  ⚠️ 2×4×2 = 16인데 군은 8개다. **완전요인설계가 아니고 군별 반복수도 미기재**
  ([원문검증 발견 6](05-데이터-설명서-원문검증.md))
- **오차가 이미 컬럼**: 처방속도(ml/h), 이론 주입시간, 실제 주입시간, 실제 유량, 오차, ABS(절대오차)
- **실제 항암 환자**: 100명, 항암제 20여 종, 암종 20여 종, 농도·총량 포함

즉 벤치 실험(생리식염수 실험실 계측)이 아니라 **실제 항암치료 현장에서 측정된 유량 오차**이고,
요인이 통제되어 있어 오차의 원인을 분해할 수 있다.

## 분석 설계의 핵심 — 통계 낚시가 아니라 물리 예측 검증

이 부분이 실현성 점수의 승부처다. "데이터를 넣고 뭐가 나오는지 보겠다"가 아니라
**유체역학에서 나온 방향성 있는 가설을 세우고 8군 설계로 검증한다**는 구조로 짠다.

중력식 수액 주입은 Hagen–Poiseuille 관계를 따른다.

```
Q ∝ ΔP · r⁴ / (μ · L)          ΔP = ρ·g·h − P_venous
```

여기서 나오는 검증 가능한 사전 가설:

| # | 가설 | 근거 | 데이터로 검증하는 방법 |
|---|---|---|---|
| H1 | 수액높이 200cm군이 150cm군보다 실제 유량이 크다 | ΔP ∝ h | 높이 주효과 |
| H2 | **처방시간이 길수록 절대오차가 커진다** | 주입 중 백이 비면서 h가 감소 → 유량이 시간에 따라 단조 감소. 긴 주입은 이 누적 감쇠에 오래 노출된다 | 처방시간 주효과. **가장 중요한 가설** |
| H3 | 5% D/W가 NS보다 느리다 | 포도당 용액의 점도 μ가 더 높다 | 수액종류 주효과 |
| H4 | 높이 × 처방시간 상호작용이 존재한다 | 높은 백은 감쇠 여유가 크므로 긴 주입에서 상대적 이점이 크다 | 2차 상호작용항 |
| H5 | 처방속도가 낮을수록 상대오차(%)가 커진다 | 저유량 영역에서 조절기 dial 분해능과 크립의 영향이 상대적으로 커진다 | 처방속도 대비 상대오차 회귀 |

**H2가 성립하면 이 제안의 임상적 핵심이 선다.** 장시간 주입 항암제일수록 오차가 크고,
장시간 주입이 필요한 약물은 대개 주입 속도 관리가 중요한 약물이다. 즉 오차가 가장
큰 구간과 오차가 가장 위험한 구간이 겹친다는 논증이 가능하다.

가설이 기각되어도 결과는 나온다. "물리 예측과 실제가 어긋나는 지점"이 곧 발견이 된다.
**어느 방향으로 나와도 보고서가 완성되는 구조.**

> **±10% 제약과의 정합**: 설명서가 밝힌 ±10%는 **전체 평균**이다. 위 가설들은
> 전부 **조건부** 진술이므로 평균이 ±10%인 것과 모순되지 않는다. 평균 ±10%
> 안에서도 8군 중 특정 군은 ±20%일 수 있고, 그 군이 어디인지가 곧 산출물이다.
> 제안서에서는 이 관계를 명시적으로 써서 "설명서를 읽고도 이걸 제안했다"를 보여준다.

## 3층 산출물

### 1층 (안심존 내부, 4시간 안에 완주) — 오차 지도
0. **실험군 구성 복원 → 데이터 품질 진단.** 8군이 3인자의 어떤 조합인지 교차표로 먼저
   확인한다(모형이 여기서 갈린다). 이어 컬럼 8("0", 설명 없음)의 정체, 컬럼 20 "분(환산)"을
   시작·종료시간으로 재계산해 정의 역추적, 연령 결측 1건, 실제 행 수(120 vs 120 이상)
1. **군간 공변량 균형 확인.** between-subject 배정이므로 8군의 성별·연령·약물·수액총량
   구성이 다르면 군 효과가 교란된다. 불균형 시 보정 모형으로 전환한다고 미리 명시
2. 8군별 오차·절대오차 분포, **높이 × 주입시간 2차 교호작용** (3차는 군 구성이 허용할 때만)
3. 조건 → 예상 편차 예측식 (선형 모형 우선, 필요시 트리 계열)
4. 약물별·암종별 하위 기술통계 (정규화된 성분 기준)

**반출 대상: 계수·요약통계·그림뿐** → 심의 통과가 쉽다. 원본은 물론 반출 불가.

> ⚠️ **부작용 분석은 넣지 않는다.** 설명서 서술부는 부작용 측정을 세 번 언급하지만
> 23개 컬럼에 부작용이 없고, "제외 기준을 적용하여 최소화"했다고 명시되어 있다.
> 서술만 믿고 설계하면 본선에서 무너진다. 상세: [원문검증](05-데이터-설명서-원문검증.md) 발견 3

### 2층 (안심존 외부, 인터넷 환경) — 정규화 + 근거 문서 RAG
Gemini 2.5 Flash Lite를 API로 호출하는 층. **환자 데이터가 전혀 들어가지 않으므로**
안심존 밖에서 자유롭게 구축·검증·시연할 수 있고, 개인정보 반출 문제도 원천적으로 없다.

- **2a 약물명 정규화**: 오염된 22개 문자열 → 표준 성분명 12개. 결과는 전수 수작업 검증
- **2b 근거 검색**: 성분별 권고 주입 시간·속도·희석 조건을 공개 문서에서 검색
- **2c 판정 생성**: 근거 인용 없이는 판정을 내리지 않는 구조 (환각 차단)

인덱싱 대상 후보(라이선스 확인 중): 식약처 의약품 허가사항, 종양간호 실무지침,
근거기반 임상간호실무지침, 국가암정보센터, DailyMed·FDA label 등.

### 3층 (결합) — 사전 보정 도구
1층의 예측식이 편차를 계산하고, 그 편차를 질의로 바꿔 2층이 근거를 검색한다.

```
입력:  약물 = X, 처방 주입시간 = 60분, 수액대 높이 = 150cm, 수액 = 5% D/W
1층 →  예상 실제 주입시간 72분 (편차 +20%)
2층 →  약물 X의 권고 주입시간은 30~60분 [출처: 허가사항 용법용량]
판정 →  권고 범위 초과. 높이 200cm 조정 시 예상 63분
```

## 참신성 논거의 축 — 두 개

**(가) 계측값이 검색 질의를 생성한다.**
기존 RAG 임상 의사결정 지원은 대부분 텍스트 질문 → 텍스트 답변이다. 이 제안은
**측정된 유량 오차가 곧 질의**가 되고, 근거 문서가 그 오차의 허용 여부를 판정한다.
계측 데이터 층과 문헌 근거 층이 서로 다른 층위인데 하나의 판정으로 합쳐진다.

→ 선행 사례 조사로 이 주장이 성립하는지 확정할 것. 성립하지 않으면
"항암 수액이라는 미개방 계측 데이터에 근거 검색을 결합한 최초 사례"로 좁힌다.

**(나) 정규화 없이는 조회가 불가능하다 — LLM이 장식이 아닌 이유.**
데이터의 항암제 컬럼은 22개 문자열이 실제로는 12개 성분이고, `Perbrolizumab`,
`Cisplain`, `Oxailplatin`, `Trastuzumab-Deruxt` 같은 오타·절단·상품명 혼입이 섞여 있다
([원문검증](05-데이터-설명서-원문검증.md) 발견 2). **어떤 의약품 데이터베이스도
`Perbrolizumab`을 조회하지 못한다.** 즉 이 데이터를 약물 근거에 연결하는 일 자체가
의미 기반 정규화를 전제한다.

심사위원의 "왜 LLM이 필요한가"에 대한 답이 여기 있다. 성능 향상 장치가 아니라
**연결 가능성의 전제 조건**이다. 그리고 22개 문자열은 **전수 수작업 검증이 가능한 크기**라
정규화 정확도를 100% 사람이 확인해 보고할 수 있다 → 환각 리스크를 제안서에서 정면으로 닫는다.

## 실현성 방어 장치

| 심사위원이 의심할 지점 | 대응 |
|---|---|
| 데이터를 못 본 상태에서 계획이 성립하나 | 인자·수준·23컬럼·오차 정의가 명시. 미기재 항목(8군 조합, 군별 반복수)은 목록화해 방문 1단계 확인으로 고정하고 모형을 분기시켜 둠 |
| 방문 1회로 분석이 끝나나 | 120행 표 데이터. 실행 수 초. 사전에 코드를 완성해 가서 실행·해석만 한다 |
| GPU 없이 되나 | 1층은 표 통계라 무관. 2층은 **안심존 밖에서 클라우드 API**로 돌므로 안심존 자원과 완전 무관 |
| 폐쇄망에서 API를 어떻게 호출하나 | **호출하지 않는다.** 이게 분리 구조의 요지. 안심존 안은 표 통계뿐 |
| 환자 데이터가 외부 API로 나가는 것 아닌가 | 2층 입력은 **공개 문서와 약물명 문자열뿐**. 환자 데이터는 API에 닿지 않는다. 수행평가 규정 준수 5점에서 유리 |
| 120행은 적다 | 8군 배정 설계, 군당 평균 15회. 주효과 검출에는 설계된 규모. 산출물 본체는 3층 도구 |
| RAG 환각 | 근거 인용 없으면 판정하지 않는 설계 + 정규화 22건 전수 수작업 검증 |
| 반출 심의 | 반출물이 계수·그림·요약통계뿐. 방문 당일 신청 → 11/6까지 충분 |
| 외부 상용 API 의존 | 조사 결과 반영 예정. 현재 방어선: 2층은 공개 문서 층이라 대체 가능하고, 1층 산출물은 API 없이도 독립적으로 성립 |
